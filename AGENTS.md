# ClubFlow PA3 assistant rules

- Read [PA3_PLAN.md](PA3_PLAN.md) for owners, browser routes, shared interfaces, workflow and acceptance. The PA3 rubric governs grading and the final brief governs ClubFlow behavior. Read the relevant contract, callers and checks before editing. An invocation by ID authorizes only that task from `brief.md` after its branch, review and checkpoint gates are met.
- Preserve PA2 history. Each member owns their feature folder and their own `docs/ai-prompts/<member>.md` and `docs/ai-logs/<member>.md`, as listed in the plan. Huy owns shared infrastructure, dependencies, `docs/api/`, `mock/` and root evidence. Only Huy merges into `main`. Route shared defects and cross-owner changes to Huy.
- Follow contract → mock → verified scaffold → branches. Treat `docs/api/` as the API source of truth. Never invent an endpoint. Stop the dependent work and report the missing operation to Huy. Never edit `docs/api/` or `mock/` during a feature task without explicit authorization. Log approved later changes in the agreed `## Changes`.
- Use React/Vite, React Router, the agreed feature exports, `useAuth()`, `apiRequest()`, native forms and locally bundled plain CSS. Call only documented relative `/api/` paths. Use the shared session for authenticated requests, including downloads. Add dependencies only with approval.
- Load main-flow data, permissions, counts and state from the API. Show loading, error with Retry, empty lists and zero totals. Map validation errors to labelled fields, keep input after failure and prevent double submits. Keep private notes, CVs and results within their authorized audience.
- Preserve semantic HTML, one h1, heading order, visible labels, keyboard navigation, readable drawers and mobile tap targets. Use feature-scoped CSS and test 360/768/1280 px. Keep the page free of clipping and horizontal scroll.
- Before each implementation request, use a clean Git checkpoint. Afterwards inspect the actual diff, including `git diff -- docs/api mock` and staged changes. Run relevant checks before reporting completion. State exactly what ran and what remains unverified.
- Keep submission documents in English and preserve verbatim messages. Each member stages their two evidence files with their feature. Record the exact invocation, task ID, `brief.md` revision, genuine follow-ups and actual checks. Huy consolidates root evidence after the verified baseline and approved merges. Integrate his campaign records before writing further Huy entries on `main`. Proposed library blocks receive no execution entries until invoked. Never fabricate test results, mistakes, corrections, review, approvals, scores or Git history. Obtain authorization before a commit, push, merge or deployment.
