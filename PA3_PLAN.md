## Shared interfaces before branching

- **Router.** React/Vite, declarative `BrowserRouter`, plain CSS and native forms. Huy registers the named exports below, role navigation, access-denied view and `*` fallback. Use router links, browser Back and an `index.html` history fallback. In Vite set both `server.proxy` and `preview.proxy` to forward `/api` to `http://localhost:3001`. Pin compatible versions at scaffolding. [Vite preview proxy](https://vite.dev/config/preview-options.html#preview-proxy) · [BrowserRouter](https://reactrouter.com/api/declarative-routers/BrowserRouter)
- **Session.** `useAuth() → {user, token, signIn(email,password), signOut()}`. Restore the API-issued session from session storage before guards run. After sign-in restore an authorized local path including query/fragment, otherwise use the role home. Clear context, storage and private view data on sign-out. Handle an expired/invalid session with sign-in and forbidden access with a denial.
- **Transport.** `apiRequest(path, {method, body, signal, responseType})` owns fetch, defaults to GET/JSON, accepts only relative `/api/…`, and attaches the active Bearer token. Support FormData (browser sets boundary) and authenticated PDF/CSV blobs. Return decoded data or throw `ApiError {status,code,message,fields}`. Proposed responses use `{items,total}` for lists, authoritative changed records for writes and `{error:{code,message,fields}}` for errors, with stable paths for nested fields.
- **Components.** Shared `LoadingState`, `ErrorState({message,onRetry})`, `EmptyState({message})`. Each screen owns its request and form state. Abort stale requests, debounce API search, retain failed inputs, disable duplicate submits. Apply the mutation response or refetch affected data once. Reload current API state on route entry. Keep review filters/page in the URL. Import global CSS once and scope feature selectors under a feature class.
- **Handoffs.** C4 owns qualifications, room choices, availability and duration. C8 reads the same configuration. Its duration selector writes to the existing setup operation and revalidates affected slots before generation. C7 links to C8. C6/C10 read the assignments confirmed by C9. C11 reads C10 assessments. Features exchange IDs through links and records through the API. No cross-feature component imports or client fixtures.

## Contract and mock handoff

1. **Index and resources.** `docs/api/README.md` defines `/api`, Bearer auth, error shape, status codes and every endpoint's method, path, roles and resource file. One numbered file per resource specifies roles, parameters, field types/required flags/limits, success response and applicable 400 (per field), 401, 403, 404, 409 and mode-induced 500. Specify role projections, filters, statistics, eligibility reasons and duplicate ID handling. End every file, including the index, with `## Changes`. Put literal paths before overlapping parameter paths for the same method. If adopted, `GET /api/applications/export` precedes `GET /api/applications/:id`. The checker credits the first matching row, so reversing them can leave the export row uncovered.
2. **Runnable examples.** For every endpoint, pair a concrete `http` request with its `http` answer. Include a JSON `POST /api/auth/login` example with `email` and `password`. Use `Authorization: Bearer {{token:<name>}}` on protected requests. For multipart use supported `sh` curl and a generated file. PDF/CSV answer blocks have status/headers and no body. Verify file contents separately.
3. **T1 handoff and example order.** Specify an Applicant-safe read for C5 slot IDs shared by C4/C8, preview versus persistent save in C8, and server revalidation on both save and confirmation. Trace adding/removing department and position rows through draft and publication. The checker runs README first, then files alphabetically, top to bottom, in **one** normal process. Use README reads on the open seed. Use the resource order auth → campaign (begin pristine walkthrough, invalid draft, publish) → setup → applications (create A01/A02, duplicate, review) → schedule (early refusal, clock past close, unassigned/conflict, repair, save, confirm) → interviews (early assessment refusal, advance clock, assess) → decisions → notifications. Put prerequisite calls in the example sequence where needed. The demo resource can end with a refused backward transition. Use predictable IDs. The checker resolves named tokens. It does not capture newly created application IDs for later requests.
4. **Server.** `node mock/server.mjs`, built-ins only, `PORT` default 3001. Load seeds from `mock/data/`, keep writes in memory and reset on restart. Stable role-bound tokens survive a restart. Log method, path, status. Scope lists, individual IDs, PDFs and exports on the server. Exclude private screening notes from Applicant/Interviewer responses. Serve readable local PDFs.
5. **Modes and accounts.** `MOCK_MODE=normal` (~150 ms), `slow` (2 s), `error` (shaped 500 for every request except sign-in), `empty` (all lists, even nested, become `[]`). Single objects still resolve in empty mode and list-derived counts are zero. In `FRONTEND.md`, use **Demo accounts** with **Name in examples**, **Role**, **E-mail**, **Password**. Use `exec` (Executive), `studentA` (Applicant), `int-content` and `int-comms` (Interviewers for their respective positions).
6. **Verification.** Restart the normal mock. From root, in a second terminal run `node tools/contract-check.mjs --base http://localhost:3001` (checker needs Node 18+). Require examples sent, full endpoint coverage, exit 0, zero FAIL. Read every NOTE for inaccurate values. The checker compares status and JSON keys at every depth. Fix against the approved contract. Restart before each full rerun.
7. **Later changes.** Huy approves first. Record date, what and why in the affected resource's `## Changes`. Use `docs/api/README.md` → `## Changes` for shared or mock-only changes, naming the mock path. Commit the amended contract before the mock and consumers. No separate changelog.
