## Shared interfaces before branching

- **Router.** React/Vite, declarative `BrowserRouter`, plain CSS and native forms. Huy registers the named exports below, role navigation, access-denied view and `*` fallback. Use router links, browser Back and an `index.html` history fallback. In Vite set both `server.proxy` and `preview.proxy` to forward `/api` to `http://localhost:3001`. Pin compatible versions at scaffolding. [Vite preview proxy](https://vite.dev/config/preview-options.html#preview-proxy) · [BrowserRouter](https://reactrouter.com/api/declarative-routers/BrowserRouter)
- **Session.** `useAuth() → {user, token, signIn(email,password), signOut()}`. Restore the API-issued session from session storage before guards run. After sign-in restore an authorized local path including query/fragment, otherwise use the role home. Clear context, storage and private view data on sign-out. Handle an expired/invalid session with sign-in and forbidden access with a denial.
- **Transport.** `apiRequest(path, {method, body, signal, responseType})` owns fetch, defaults to GET/JSON, accepts only relative `/api/…`, and attaches the active Bearer token. Support FormData (browser sets boundary) and authenticated PDF/CSV blobs. Return decoded data or throw `ApiError {status,code,message,fields}`. Proposed responses use `{items,total}` for lists, authoritative changed records for writes and `{error:{code,message,fields}}` for errors, with stable paths for nested fields.
- **Components.** Shared `LoadingState`, `ErrorState({message,onRetry})`, `EmptyState({message})`. Each screen owns its request and form state. Abort stale requests, debounce API search, retain failed inputs, disable duplicate submits. Apply the mutation response or refetch affected data once. Reload current API state on route entry. Keep review filters/page in the URL. Import global CSS once and scope feature selectors under a feature class.
- **Handoffs.** C4 owns qualifications, room choices, availability and duration. C8 reads the same configuration. Its duration selector updates the interview grid and revalidates assignments within the frozen Applicant availability windows. C7 links to C8. C6/C10 read the assignments confirmed by C9. C11 reads each confirmed case, including cases without assessments. Decisions are per application and final release is campaign-wide. Features exchange IDs through links and records through the API. No cross-feature component imports or client fixtures.
